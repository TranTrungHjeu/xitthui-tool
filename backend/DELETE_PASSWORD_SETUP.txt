# Direct Delete Password (REQUIRED for /trial-report/reports/:id/direct-delete)

The trial-report delete flow is now password-gated. Anyone who knows
this shared password can delete a report immediately — it replaces
the old 2-step request/review workflow.

Pick a strong, internal-only password. Anyone with read access to the
backend `.env` (or the running process) can see the cleartext value.

Set it via one of:

  TRIAL_REPORT_DELETE_PASSWORD=<your-password-here>      node server.js
  echo 'TRIAL_REPORT_DELETE_PASSWORD=<...>' >> .env      # then `npm run dev`

To temporarily disable the gate (only for local testing):

  TRIAL_REPORT_DELETE_PASSWORD_DISABLED=true

Endpoints that use the gate:

  POST /trial-report/reports/:id/direct-delete     body: { password }

On any other endpoint that accepts `password`, the same gate applies.
Mistyped passwords return 401 EWRONGPASSWORD — the comparison uses
`crypto.timingSafeEqual` so callers cannot time-attack the password.

Audit trail: every successful delete writes one row to
`trial_report_logs` with `action: "delete"` and `metadata.source =
"delete-direct"` (or `"delete"` for the legacy internal escape hatch
`POST /trial-report/reports/:id/delete`).
